# Dependencias de la aplicación.
#
# Python 3.10 de 64 bits: el wheel de stapipy que trae el SDK de Sentech es cp310,
# así que la versión del intérprete no es libre.
#
#   Windows:  .venv\Scripts\python.exe -m pip install -r requirements.txt
#   Linux:    .venv/bin/python -m pip install -r requirements.txt

# Núcleo
# numpy queda por debajo de 2.0: el torch de NVIDIA para la Jetson y OpenCV 4.8 están
# compilados contra la ABI de numpy 1.x.
numpy>=1.24,<2.0
PyYAML>=6.0

# GUI y hilos de Qt: los QThread de system/ dependen de esto aunque no haya
# ventana, porque las señales son el cableado entre subsistemas.
#
# Versión exacta, la misma en la PC y en la Jetson: la interfaz se prueba en una y corre
# en la otra. Es la más nueva con wheel aarch64 para el glibc 2.35 de Ubuntu 22.04
# (JetPack 6); las siguientes piden un glibc más nuevo. Subirla es subirla en los dos
# lados, y sólo cuando la Jetson tenga wheel.
PySide6==6.8.0.2

# Métricas de hardware (CPU, RAM, disco, contadores de red) para system_monitor.
# Multiplataforma: la misma API responde en Windows y en el aarch64 de la Jetson.
psutil>=5.9

# OpenCV de la misma época que numpy 1.x: los wheels 4.9+ se compilan contra la ABI
# de numpy 2 y no cargan con numpy 1.
#
# Una variante por plataforma, y las dos instaladas a la vez se pisan. En Windows va la
# de GUI, porque manual_test/camera_live_view.py muestra el feed con cv2.imshow. En Linux
# la headless: el wheel con GUI trae su propio Qt 5 y apunta la ruta de plugins de Qt a
# la suya, y eso le gana a PySide6 cuando cv2 se importa antes que la ventana.
opencv-python>=4.8,<4.9 ; sys_platform == "win32"
opencv-python-headless>=4.8,<4.9 ; sys_platform == "linux"

# Cámaras Basler. El wheel incluye su propio runtime de pylon, así que alcanza para
# capturar: el SDK completo (viewer, IP Configurator, filter driver) es opcional y lo
# cubre setup/cameras/.
pypylon>=2.1.0

# Cámaras Sentech / Omron: stapipy NO está en PyPI. Lo instala el script de setup
# desde el wheel que hay que copiar a packages/:
#   Windows: setup\cameras\windows\sentech.ps1
#   Linux:   setup/cameras/linux/sentech.sh
# Se deja asentado acá porque es una dependencia real de la app, aunque pip no la
# pueda resolver.

# Servidor Modbus esclavo (system/modbus). Versión exacta, la misma en la PC y en la
# Jetson: system/modbus/server.py reemplaza `async_OLD_getValues`, el método interno por
# el que pymodbus 3.15 lee el datastore, para que la lectura del PLC tome el lock de
# escritura y nunca vea medio bloque. Si otra versión lee por otro método, la lectura
# esquiva el lock sin que nada falle. Subirla es correr test/modbus/test_server.py con
# la nueva; en la 4.0 además desaparece ModbusSimulatorContext.
pymodbus==3.15.0

# pymodbus no declara ninguna dependencia dura: el soporte de puerto serie es un
# extra. Sin pyserial el servidor Modbus RTU falla al arrancar —el TCP no lo
# necesita— y el motivo que se lee en el log es la librería faltante, no el puerto.
pyserial>=3.5

# Backends de telemetría (system/telemetry/backends). Los dos son opcionales: sin la
# librería instalada el backend degrada a no-op y lo avisa por `status`, así que
# se pueden sacar de acá en una instalación que no publique hacia afuera.
influxdb-client>=1.36
paho-mqtt>=1.6,<3

# Inferencia: NO va acá. El framework del modelo de cada fork —torch, ultralytics,
# TensorRT, el que use— se declara en setup/jetson/ y se instala sólo en el equipo: torch
# y torchvision para la Jetson son wheels de NVIDIA que no están en PyPI, y los de PyPI
# instalan una build que no ve la GPU. En la PC de desarrollo no hace falta ninguno: el
# modelo `mock` cubre el camino entero y la suite de tests corre sin ellos.

# Entradas y salidas digitales de la Jetson (system/gpio_control.py), sobre la API v2 de
# libgpiod: `request_lines` y `gpiod.line` no existen en la v1, que es la que trae apt en
# Ubuntu 22.04 como python3-libgpiod. Éste es el de PyPI, que la trae adentro. Sólo
# Linux: en Windows no se instala y el módulo degrada a modo simulado.
gpiod>=2.1,<3 ; sys_platform == "linux"

# Firma de las licencias (system/license). Ed25519: la clave pública son 32 bytes que
# entran en una línea del código y no hay parámetros que elegir mal. Hay wheels cp310
# para win_amd64 y para el aarch64 de la Jetson, así que no pelea con el pin de Python.
#
# A diferencia de los backends de telemetría, sin esta librería el módulo NO degrada a
# no-op: un verificador que no puede verificar rechaza todo. Un candado que no cierra
# tiene que quedar cerrado.
cryptography>=42.0

# Tests
pytest>=7.4
